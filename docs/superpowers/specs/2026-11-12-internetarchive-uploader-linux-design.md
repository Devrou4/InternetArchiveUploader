# InternetArchiveUploader Linux 增强版需求与设计

- 日期：2026-11-12
- 上游：https://github.com/Devrou4/InternetArchiveUploader
- 状态：用户已更新并确认本文；所有需要图形交互的测试由用户负责。尚未执行 Fork 或实现。

## 1. 目标和已确认行为

基于上游 Fork，保留 Python + PySide6 + internetarchive 技术栈，增强 Linux 桌面支持、认证配置路径管理、多文件拖拽任务队列、文件级并发、类型推断和 Linux 自动构建。

用户已确认：一次拖入多个文件，默认每个文件形成独立任务，共用用户指定的 item identifier；允许为单个任务指定不同 item。

`ia upload NintendoSwitchGame_TotK` 中的 `NintendoSwitchGame_TotK` 是 identifier，不是 title。一个 item 可以包含多个文件；metadata 和 mediatype 属于 item 级配置。

## 2. 上游现状与可行性

根据已检查的上游 main.py、requirements.txt 和 README：

- 使用 PySide6，已有 Linux 平台分支，但未实测 Linux 桌面兼容性。
- 固定使用当前目录下的 ./ia.ini。
- 使用单个上传工作线程，全局重定向 stdout/stderr。
- 发现 identifier 已存在时阻止上传。
- 有常规 metadata 输入和额外字段对话框。
- identifier 的本地小写限制需按 IA 当前规则重新核实，不应擅自将用户输入转为小写。

全部需求技术上可实现。并发队列需要调整架构；同一 item 并发、库会话隔离、进度接口及 Qt 打包须提前验证。文档结论不代表软件已经通过运行测试。

## 3. 技术选择

推荐扩展现有 PySide6 GUI，直接调用 internetarchive Python 库，复用现有代码。

替代方案：GUI 包装 ia 子进程，隔离较方便但需解析命令输出；重写 Web GUI 则改造范围过大。首期不采用这两个方案。

## 4. 功能需求

### FR-01 Fork 与上游管理

1. Fork 到用户指定 GitHub 账号或组织，实施前确认目标所有者。
2. origin 指向 Fork，upstream 指向原仓库。
3. 保留提交历史、许可证和上游来源说明。
4. README 增加增强功能、Linux 运行、配置和构建说明。
5. 不提交密钥、ia.ini、用户上传文件或运行日志。

验收：Fork 可独立开发和运行 Actions，保留上游关联。

### FR-02 Linux 图形化支持

建议首期支持 x86_64，验证 Ubuntu 22.04、24.04；覆盖 X11 与 Wayland 桌面的可用 Qt 后端或 XWayland。不承诺所有发行版及 ARM64。

1. 支持源码和打包产物运行。
2. 资源路径不依赖当前工作目录；配置和日志存入用户可写目录。
3. 检查 Qt 平台主题、桌面门户和防休眠兼容性；防休眠失效不得阻断上传。
4. 网络操作在后台执行，GUI 不阻塞。
5. 尽量保持 Windows 兼容，不引入 Linux 专有核心业务逻辑。

验收：任意工作目录启动资源正常；完成认证和小文件上传；目标 X11/Wayland 桌面分别实测。无头 CI 只作为冒烟测试，不替代桌面测试。

### FR-03 自定义 ia.ini 路径

提供命令行 `--config /path/to/ia.ini` 和 GUI 的选择/创建配置文件入口。

加载优先级：命令行参数 > GUI 上次保存路径 > `${XDG_CONFIG_HOME:-~/.config}/internetarchive-uploader/ia.ini`。

1. 显示实际使用路径；支持中文和空格路径。
2. 不存在时确认创建；损坏、不可写、认证失败时明确提示，不静默切换账号。
3. 登录、查询和上传均使用指定配置。
4. 旧 ./ia.ini 提供导入或迁移提示，不静默迁移。
5. Linux 新建凭据文件仅当前用户可读写；日志不输出凭据。
6. 有运行任务时不允许切换账号。排队任务必须明确绑定使用的配置，不得因界面切换意外上传到其他账号。

验收：非默认路径可完整认证、查询与上传；无需安装目录写权限。

### FR-04 多文件拖拽与任务队列

1. 支持拖入多个普通文件和文件选择器多选，一文件一任务。
2. 导入不立即上传，允许配置后启动。
3. 表格展示路径、大小、identifier、远程文件名、识别类型、状态、进度和错误。
4. 检查存在性、可读性、重复导入以及同一 item 内远程路径冲突。
5. 默认统一指定 identifier，支持批量修改和单任务修改；title 单独填写。
6. 运行任务不可编辑；待执行任务可编辑、移除。
7. 支持启动、停止派发新任务和重试失败任务。停止派发不等于中断活动请求。
8. 状态至少包含：待配置、排队、上传中、成功、失败。自动重试期间显示重试信息。

新 item：用户确认统一 metadata 后，只执行一次初始化，成功后派发后续文件。为避免仅有 metadata 的空条目创建兼容问题，可由首个文件完成初始化上传；具体方法在库验证后确定。

已有 item：允许有权限的账号追加文件，读取现有 metadata 供查看，默认不覆盖。查询错误不可解释为条目不存在。无权限明确失败。

同名远程文件不得静默覆盖，需跳过或明确确认。新任务彼此同名也应在上传前阻止或解决。

提供可获得的真实进度，不编造百分比。如果没有稳定字节进度接口，展示上传中、完成文件数和日志。成功表示上传请求完成，不代表后台派生任务完成；提供条目链接。

验收：多文件导入、共同/不同 item、新建/追加、冲突检查及失败重试均可用。

### FR-05 可配置文件级并发

建议默认 2，范围 1～8；这是同时上传的文件数，不是单个文件的分片并发。

1. 有上限的工作池；减少并发不强制终止活动任务，只控制新派发。
2. 独立任务状态和结构化日志，不依赖全局 stdout/stderr 归属日志。
3. 每个工作执行单元使用隔离会话，或采用经证实安全的共享策略。
4. 对可恢复网络错误、限流采用有限次数退避重试；尊重服务端 Retry-After。认证/权限错误不无限重试。
5. 相同 identifier 的初始化加锁，初始化成功后才并发追加；只提交统一 item metadata。
6. 提交结果不明时先核实远程状态，避免盲目重复操作。
7. 如果实测同 item 并发不可靠，则降级为 item 内串行、不同 item 并发，并清楚告知用户。
8. 应用退出时提示活动任务，不直接强制销毁工作线程；安全等待或用户明确选择退出，不承诺跨进程续传。

验收：稳定设置为 N 时不超过 N 个活动文件上传；调低时现有任务自然完成；单任务失败不丢失其他任务；同 item 不重复初始化。

### FR-06 文件识别与 Metadata 预填

识别范围是文件格式和推荐 mediatype，不是自动识别作品语义、作者、版权或年份。

策略：扩展名/MIME 映射 + 常见文件头校验；矛盾或未知时标记需确认。不执行文件，不自动解压大文件。

推荐映射：

| 类别 | mediatype |
|---|---|
| MP3/FLAC/WAV | audio |
| MP4/MKV/WEBM | movies |
| JPG/PNG/WEBP | image |
| PDF/EPUB/TXT | texts |
| 已知软件包/游戏镜像 | software，提示人工确认 |
| ZIP/7Z/RAR、未知格式 | 不确定，手动选择 |

1. 新条目 title 可由文件名去扩展名预填；多文件共用条目使用统一标题。
2. creator、description、subject 使用用户模板或留空，不编造。
3. collection 只能提供与权限匹配的建议，不假定任意集合可写。
4. 同 item 类型混合时提示冲突，由用户确认统一类型。
5. 已有 item 保留既有类型，不自动覆盖。
6. 用户手动修改优先于后续自动识别。

验收：常见格式正确推荐；压缩包不被无提示误分类；人工设置不被覆盖；同 item 不争相写入不同 metadata。

### FR-07 Linux 构建 Workflow

新增 `.github/workflows/build-linux.yml`。

触发：PR 测试与构建；默认分支推送保存 Artifact；v* 标签发布 Release；workflow_dispatch 手动构建。

首期建议 PyInstaller 目录式构建，打包为：

- InternetArchiveUploader-<version>-linux-x86_64.tar.gz
- SHA256SUMS

包含运行时、Qt 必要组件、资源、许可证、README 与版本信息，不包含认证和用户数据。AppImage 作为后续增强。

流程：检出 → 固定 Python → 安装系统和 Python 依赖 → 单元测试 → 虚拟显示 GUI 冒烟测试 → 打包 → 产物启动测试 → 压缩/校验 → Artifact/Release。

1. 构建基线兼容承诺的最旧系统；确认依赖固定版本实际可用。
2. 测试不需要真实 IA 密钥；网络行为模拟，真实上传使用获授权测试账号单独验证。
3. 不把凭据写入 Actions 日志或 Artifact。
4. 仅 Release 发布任务获得必要写权限；PR 不发布。

验收：目标系统未安装 Python 时，下载产物可启动；检查资源、配置选择和 GUI 基本交互。真实上传另外验证。

## 5. 架构和数据流

- ConfigManager：解析路径、权限、认证配置。
- MetadataDetector：格式识别和默认字段建议。
- ItemService：存在性查询、初始化、权限错误和冲突处理。
- TaskQueue：任务状态、并发额度、重试派发。
- UploadWorker：单文件传输和结构化事件。
- GUI：配置入口、item 表单、任务表、并发控件及日志。

ItemConfig 保存 identifier、统一 metadata 和初始化状态；UploadTask 保存文件路径、远程路径、关联 ItemConfig、配置绑定及状态。GUI 经信号接收后台事件，不由工作线程直接更新控件。

数据流：导入 → 校验/识别 → 用户确认 item 和 metadata → 查询远端/检查冲突 → 初始化新 item → 按并发额度上传 → 记录结果和错误。

## 6. 测试与验收

单元测试：配置优先级、路径处理、格式映射、人工覆盖保护、任务状态、远程路径冲突、调度上限、重试策略、item 初始化互斥。

模拟集成测试：查询失败、新条目、已有条目、权限失败、限流、网络中断、提交结果不明、配置切换限制。

GUI 测试：多文件拖拽和选择、批量/单项修改、停止派发、重试、窗口关闭流程、非阻塞操作。

打包测试：资源加载、任意工作目录启动、非默认配置、无 Python 桌面启动、产物无凭据。

所有真实上传需明确授权且使用可合法上传的测试文件。构建通过不等于真实上传或所有桌面兼容测试通过。

### FR-08 代理配置（新增）

用户要求：支持填写代理地址，例如 `http://192.168.195.18:20171`。

1. 图形设置与 `--proxy` 命令行两个入口；沿用配置优先级（CLI > 上次保存 > 无）。
2. 代理必须同时作用于登录、条目查询和上传（含 IAS3 端点）。
3. 空值表示直连；必须校验协议与端口，错误输入明确报错，不回退直连。
4. 支持 http/https/socks5(h)；SOCKS 缺依赖时给出安装提示。
5. 代理 URL 中的凭据不得出现在日志、界面或异常文本中。
6. 有运行中任务时禁止更换代理。

验收：经代理可完成登录、查询和上传；错误代理不影响已保存配置；凭据不泄露。
