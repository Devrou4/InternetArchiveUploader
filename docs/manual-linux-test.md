# Linux 手工验收清单（由用户执行）

自动化测试覆盖逻辑与非交互路径；以下项目需要真实桌面与你的判断。
每项记录：环境 / 步骤 / 期望 / 实际 / 结论。

## 准备

- [ ] 系统：Ubuntu 版本、会话类型（X11 或 Wayland）、桌面环境
- [ ] 产物来源：CI Artifact 或 Release，记录 run 链接与文件名
- [ ] 测试账号具备上传权限，使用可合法上传的测试文件
- [ ] 备份现有 `ia.ini`

## A. 启动与资源

- [ ] A1 从 `/tmp` 等无关目录启动产物，图标与 logo 正常显示
- [ ] A2 Wayland 会话可正常显示窗口（或通过 XWayland 正常显示）
- [ ] A3 目标机器未安装 Python 时仍能启动
- [ ] A4 无桌面门户/防休眠不可用时，只出现提示，不阻止上传

## B. 认证配置

- [ ] B1 `--config "/tmp/我的 配置/ia.ini"` 启动，界面显示该路径
- [ ] B2 首次登录在该路径创建文件，权限为 `600`（`stat -c %a`）
- [ ] B3 指向不存在/损坏文件时明确报错，不使用其他账号
- [ ] B4 运行中禁止切换配置

## H. 代理

- [ ] H0 **未登录时**在登录窗口的 `proxy` 框填 `http://192.168.195.18:20171`，能成功登录（无代理登录会失败）
- [ ] H0b 登录框填写的代理登录后带入主窗口，上传同样走代理
- [ ] H1 `--proxy http://192.168.195.18:20171` 启动，界面显示脱敏后的代理
- [ ] H2 无代理时标为 `none`，可正常登录
- [ ] H3 填错格式（如漏写 `http://`）时提示，且不关闭设置窗口
- [ ] H4 代理不可达时给出明确失败提示，不静默直连
- [ ] H5 代理启用后登录、查询、上传均成功
- [ ] H6 含用户名密码的代理，界面与日志中只出现 `***:***`

## C. 导入与任务

- [ ] C1 一次拖入 3 个文件，生成 3 行任务，默认同一 identifier
- [ ] C2 拖入文件夹或网页链接时给出提示且不新增任务
- [ ] C3 重复拖入同一文件不产生重复行
- [ ] C4 批量修改选中行的 identifier；单独修改一行
- [ ] C5 上传中的行不可编辑
- [ ] C6 同名远程文件显示冲突，且无法开始上传

## D. 类型识别

- [ ] D1 mp3/mp4/png/pdf 分别推荐 audio/movies/image/texts
- [ ] D2 zip/7z 显示“需人工确认”，不自动归类
- [ ] D3 手动改过类型后再拖入文件，不被自动值覆盖
- [ ] D4 混合类型共用一个 item 时提示冲突

## E. 上传与并发

- [ ] E1 并发设为 2，观察同时最多 2 个文件在传
- [ ] E2 上传中把并发调为 1，运行中的任务不被中断
- [ ] E3 新建 item：第一个文件创建条目后其余文件追加，不重复建条目
- [ ] E4 已有 item：追加文件成功，原 metadata 未被覆盖
- [ ] E5 “Stop dispatching” 后不再派发新文件，运行中的继续
- [ ] E6 一个文件失败不影响其他 item 的任务
- [ ] E7 “Retry failed” 后重试成功
- [ ] E8 上传完成后打开 archive.org 条目页核对文件与 metadata

## F. 关闭与退出

- [ ] F1 有上传时关闭窗口会确认，取消则继续运行
- [ ] F2 选择等待时界面不假死，完成后退出
- [ ] F3 仍在传输时再次关闭会被拒绝并提示

## G. 安全

- [ ] G1 日志与界面不出现密码或 Secret Key
- [ ] G2 产物解压目录内不存在 `ia.ini` 或上传状态文件
- [ ] G3 Release 附件包含 `SHA256SUMS` 且校验通过
